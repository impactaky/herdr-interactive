# 複数の ask をまとめて送る（2026-10-28）

[English](003-batch.en.md)

## 文脈

一つの画面や複数の pane で気になる箇所がいくつもあるとき、1件ずつ送ると agent が1件ごとに作業を始めることがあり、関係する質問をまとめて伝えにくい。

## 決定

1. 入力枠の Ctrl+A で ask を送らずにため、同じ静止画面の範囲選択に戻る（初版は閉じていたが、続けて選べないと利用者が指摘し同日変更）。次の Enter でためた分と今の1件を1つの文として送る。Enter は従来どおり「送る」。Esc は書いていた1件だけを取り消し、Ctrl+X でためた分を捨てる。
2. まとめた文は件数を含む見出し、引用が指示ではないという注記、番号付きの項目の順にする。各項目には送り元のタイトル、送り先と違う pane なら送り元の情報、引用、ひとことを並べる。1件だけのときは従来の形。文の例は [README](../../README.ja.md#送る文) にある。
3. 記録の形は変えず、1件ごとに1行を書き、まとめて送った行に共通の `batch_id` と `batch_index`、`batch_size` を付ける。
4. ためた分は `$XDG_RUNTIME_DIR/herdr-interactive/` に Herdr session ごとに置く。`XDG_RUNTIME_DIR` がなければ、システムの一時ディレクトリ内の `herdr-interactive-<uid>/` に置く。長期保存は目的としないが、session 終了時に消す処理はなく、残る期間は保存先の管理に依存する。ためられる上限は20件で、送信時の1件は別に加えられる。

## 代替案

- ためる操作を別のキー割り当て（plugin action）にする: 入力枠の外で操作が増え、どの ask をためたかが分かりにくい。
- まとめた送信を1行の記録にする: 既存の jq の例と項目の意味が変わる。
- ためた分を state directory に置いて再起動後も残す: 利用者が不要と判断した。
- キーを Ctrl+S / Ctrl+Q にする: 端末や ssh のフロー制御に取られることがある。

## 結果

送信の失敗はまとめた全件に記録し、ためた分を消して自動で送り直さない。記録先を開けなければ、送信も追記もせず、ためた分を残す。
