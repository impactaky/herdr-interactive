# 送った質問を振り返る

[English](review-reds.en.md)

- 誰が: 開発者
- 目的: 過去にどの画面のどこを、どの agent に、何と聞いたかを後から確かめる
- 始まり: 開発者が記録のファイルを開く

## 基本シナリオ

1. 開発者が README に書かれた場所にある記録のファイルを開く。
2. 記録には、Enter で送る操作をした ask ごとに1行あり、時刻・送り元・送り先・引用・ひとこと・送れたかが残る。
3. 開発者が jq などで時刻や送り元で絞り込み、目的の質問を見つける。

## extension

- **送信を確認できなかった質問を探す**: 手順 3 で `delivery` が `sent` 以外の行に絞る。agent がいなかった質問と送信に失敗した質問が見つかる。目的に届く。
- **記録がない**: 手順 1 でファイルがない。まだ記録されていないか、記録が削除・移動された可能性がある。目的に届かない。

## 出力の例

shell から送った質問を agent の画面でも確認できる。下の JSONL は記録の形式の例。

![送信した質問](../images/shell-to-agent.png)

記録の1行（例、整形済み）:

```json
{"timestamp": "2026-10-28T03:06:24+00:00",
 "source": {"pane_id": "w1K:p3C", "title": "...", "cwd": "...", "tab_id": "w1K:t2Q"},
 "destination": {"pane_id": "w1K:p2A", "kind": "claude"},
 "quote": "  試し方は前と同じで、キーだけが変わります。", "quote_origin": "frozen",
 "quote_truncated": false, "quote_original_length": 23,
 "note": "テスト", "delivery": "sent"}
```

## 制約

- 事前条件: Enter で送る操作をし、一度以上記録されている。
- 事後条件: 記録は追記だけで、plugin は書き換えも削除もしない。ファイルは本人だけがアクセスできる。
- 合意: 記録の項目と置き場（2026-10-27）。jq での絞り込みは仮定（専用の画面は作らない）。

## test case

| 通るシナリオ | 確かめること | 実行するもの |
|---|---|---|
| 基本シナリオ | 記録先を開ける場合、Enter で送る操作をするたびに1行増え、上の項目がすべてある。新規作成したファイルの権限が 0600 | `tests/` |
| 基本シナリオ | README の jq の例で、送り元で絞り込める | README の例を実行、メンテナが確認 |
| 送信を確認できなかった質問を探す | agent がいない質問と取り消しの質問を区別でき、取り消しは記録されない | `tests/` |

## 扱わないもの

- 記録を見る専用の画面。必要になったら別のユースケースにする。
- 記録の共有や同期。
