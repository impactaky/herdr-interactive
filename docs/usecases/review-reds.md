# 送った質問を振り返る

- 誰が: 開発者
- 目的: 過去にどの画面のどこを、どの agent に、何と聞いたかを後から確かめる
- 始まり: 開発者が記録のファイルを開く

## 基本シナリオ

1. 開発者が README に書かれた場所にある記録のファイルを開く。
2. システム（記録）は、送った質問ごとに1行で、時刻・送り元 pane・送り先・引用・ひとこと・送れたかを持つ。
3. 開発者が jq などで時刻や送り元で絞り込み、目的の質問を見つける。

## extension

- **送らなかった質問を探す**: 手順 3 で送れたかの値で絞る。agent がいなかった質問と送信に失敗した質問が見つかる。目的に届く。
- **記録がない**: 手順 1 でファイルがない。まだ一度も質問していない。目的に届かない。

## 出力の例

shell から送った質問を agent の画面でも確認できる。記録は下の JSONL として残る。

![送信した質問](../images/shell-to-agent.png)

記録の1行（例、整形済み）:

```json
{"timestamp": "2026-10-28T03:06:24+00:00",
 "source": {"pane_id": "w1K:p3C", "title": "...", "cwd": "...", "tab_id": "w1K:t2Q"},
 "destination": {"pane_id": "w1K:p3C", "kind": "claude"},
 "quote": "  試し方は前と同じで、キーだけが変わります。", "quote_origin": "frozen",
 "quote_truncated": false, "quote_original_length": 23,
 "note": "テスト", "delivery": "sent"}
```

## 制約

- 事前条件: 一度以上、質問した。
- 事後条件: 記録は追記だけで、plugin は書き換えも削除もしない。ファイルは本人だけが読める。
- 合意: 記録の項目と置き場（2026-10-27）。jq での絞り込みは仮定（専用の画面は作らない）。

## test case

| 通るシナリオ | 確かめること | 実行するもの |
|---|---|---|
| 基本シナリオ | 送るたびに1行増え、上の項目がすべてある。ファイルの権限が 0600 | `tests/` |
| 基本シナリオ | README の jq の例で、送り元 pane で絞り込める | README の例を実行、親が確認 |
| 送らなかった質問を探す | agent がいない質問と取り消しの質問を区別でき、取り消しは記録されない | `tests/` |

## 扱わないもの

- 記録を見る専用の画面。必要になったら別のユースケースにする。
- 記録の共有や同期。
